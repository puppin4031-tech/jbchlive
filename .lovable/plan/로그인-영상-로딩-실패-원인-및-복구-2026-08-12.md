# 로그인·영상 로딩 실패 원인 및 복구

## 결론: 보안 문제 아님

코드나 권한(RLS) 문제가 아니라, **백엔드 인스턴스가 응답하지 않는 인프라 장애**입니다. 방금 확인한 내용:

- 데이터 조회(REST) 요청: 응답 없이 타임아웃
- DB 직접 쿼리: "connection timeout"으로 실패
- 백엔드 메트릭 조회: 타임아웃
- 관리 콘솔 상의 상태 표시만 "정상"

즉 데이터베이스와 인증 서버가 살아있다고 표시되지만 실제로는 요청을 처리하지 못하는 상태입니다. 로그인(인증 API)과 영상 목록(DB 조회)이 동시에 안 되는 이유가 이것으로 설명됩니다. 데이터가 삭제된 정황은 없습니다.

## 복구 절차

1. 백엔드 재시작 실행 (몇 분간 서비스 중단)
2. 재시작 후 상태가 정상으로 돌아올 때까지 확인
3. 데이터 무결성 점검: 채널·설교·사용자 레코드 수 조회
4. 인증 로그 확인으로 로그인 정상 동작 검증
5. 미리보기에서 홈 화면 영상 목록과 Google 로그인 실제 동작 확인

## 재시작 후에도 안 될 경우

- 인증 로그와 DB 로그를 조회해 오류 원인 특정
- 장시간 걸리는 쿼리(slow queries) 점검
- 그래도 응답이 없으면 인프라 지원 문의 필요 (앱 코드 수정으로 우회하지 않음)

## 기술 메모

- 앱 코드(`AuthContext`, `Index.tsx`, RLS 정책)는 변경하지 않습니다. 장애 원인이 코드가 아니므로 수정 시 오히려 리스크가 커집니다.
- 재시작은 `supabase--restart`(Lovable Cloud 백엔드 재시작)로 수행하고, 이후 상태 확인이 정상일 때만 쿼리를 실행합니다.
