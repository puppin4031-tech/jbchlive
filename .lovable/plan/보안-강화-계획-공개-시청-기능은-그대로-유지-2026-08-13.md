# 보안 강화 계획 (공개 시청 기능은 그대로 유지)

전체 점검 결과, 비로그인 시청 구조 자체는 안전하게 잘 잡혀 있습니다(모든 테이블 RLS 활성화, 라이브/영상 조회는 공개 정책으로 허용). 다만 **관리자 권한 우회**와 **송출 키 노출** 두 가지 실제 취약점이 확인됐고, 그 외 방어 강화 포인트가 있습니다.

유지되는 것: 로그인 없이 링크만으로 라이브/영상 시청, 채널 목록·검색·다시보기 열람. 이번 작업으로 익명 시청 경로는 하나도 막지 않습니다.

## 1. 치명적: 송출(RTMP) 키가 익명에게 노출됨

`channels` 테이블의 공개 조회 정책이 행 전체를 반환하므로, 누구나 API로 `gcp_input_uri`(RTMP 인제스트 주소 = 방송 탈취 가능한 자격증명)를 읽을 수 있습니다.

조치:
- 이미 존재하지만 비어 있는 소유자 전용 테이블 `channel_stream_keys`로 RTMP 주소를 이전
- `channels.gcp_input_uri` 값은 비우고(컬럼은 유지해 화면 깨짐 방지), 엣지 함수는 서비스 롤로 새 위치에 기록
- 방송자/관리자 화면은 기존 `get_channel_rtmp()` 함수(소유자·관리자만 반환)로 조회하도록 변경

## 2. 치명적: 채널 소유자가 스스로 승인/정지해제 가능

`Owners can update own channels` 정책에 컬럼 제한이 없어, 소유자가 API로 `is_approved=true`, `is_suspended=false`를 직접 설정해 관리자 심사를 우회할 수 있습니다.

조치: 관리자 외에는 `is_approved`, `is_suspended`, `suspended_reason`, `owner_id`, `subscriber_count`, `gcp_*` 값을 변경해도 기존 값이 강제 유지되도록 트리거를 추가합니다(오류 대신 값 보존이라 기존 저장 화면은 그대로 동작).

## 3. 회원정보 최소 노출

현재 로그인한 모든 사용자가 다른 사용자의 `church_name`, `position`까지 조회할 수 있습니다.

조치: 프로필 공개 범위를 표시용(`display_name`, `avatar_url`)으로 좁히고, 소속·직분은 본인과 관리자만 조회 가능하도록 정책을 분리합니다. 이메일은 애초에 공개 테이블에 없으므로 그대로 안전합니다.

## 4. 외부 공격면 축소

- 엣지 함수 CORS가 `*` 전체 허용 → 프로덕션·프리뷰 도메인 화이트리스트로 제한(공개 재생 경로인 HLS 프록시·드라이브 프록시는 재생 호환성을 위해 예외 유지)
- `sermon-chat`(AI 채팅)이 인증 없이 열려 있어 크레딧 소모형 남용이 가능 → IP·사용자 단위 요청 제한과 입력 길이 제한 추가
- `drive-proxy`에 요청 크기/타임아웃 가드 추가(SSRF는 파일 ID 정규식으로 이미 차단됨)
- 내부용 SECURITY DEFINER 함수(알림·집계·트리거용)의 클라이언트 실행 권한 회수 → 린터 경고 2건 해소

## 5. 검증

- 익명 세션으로 홈·라이브·영상 시청 경로 재확인(브라우저 자동화)
- 익명/일반 사용자 토큰으로 RTMP 주소 조회 시도 → 차단 확인
- 소유자 토큰으로 자기 채널 승인 시도 → 값 보존 확인
- 보안 스캐너 재실행으로 error 2건 해소 확인

## 기술 메모

DB 마이그레이션 1건(정책·트리거·권한 회수·스트림 키 이관), 엣지 함수 3개 수정(`live-stream`, `sermon-chat`, `drive-proxy`), 프론트 소폭 수정(`ChannelSettingsPage`, `AdminPage`의 RTMP 표시부). 스키마 컬럼 삭제는 하지 않으므로 롤백이 쉽습니다.
