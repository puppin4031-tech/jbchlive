# 3시간 하드 캡 빈틈 보완 (STARTING 상태 예외 제거)

## 현재 확인된 상태

- 워치독 크론은 30초마다 정상 실행 중이며 응답 코드 200 (실측 확인).
- `HARD_MAX_MINUTES = 180`: `live_started_at` 기준 180분 경과 시 시청자 수·OBS 상태와 무관하게 자동 종료(`auto_max_duration`)됩니다.
- 단, GCP 상태가 `STARTING`인 채널은 워치독 루프 상단에서 `continue`로 건너뛰기 때문에 180분 캡을 포함한 모든 자동 종료 로직이 적용되지 않습니다.

## 변경 내용

`supabase/functions/live-stream/index.ts`의 `autoStopIdleChannels`에서 STARTING 예외 처리를 조건부로 바꿉니다.

- STARTING이면서 경과 시간이 180분 **미만**인 경우: 지금처럼 건너뜀 (시작 LRO 방해 방지 유지)
- STARTING이면서 경과 시간이 180분 **이상**인 경우: 강제 종료 경로 실행
  - GCP 정지 시도(실패해도 무시)
  - DB를 반드시 오프라인 처리 (`is_live=false`, 상태/시간 정리)
  - 라이브 세션 종료 기록 사유 `auto_max_duration`
  - 송출자에게 자동 종료 알림 발송

기존 정상 경로(180분 캡, 저시청자 20분, OBS 끊김 1분 유예, 방송 시작/프로비저닝 코드)는 그대로 유지합니다.

## 검증

- 배포 후 워치독 응답이 계속 200인지 확인
- 현재 라이브 채널 목록과 경과 시간을 조회해 180분 초과 채널이 남아 있지 않은지 확인
