# 실시간 영상 `http: 0` 재생 오류 수정

## 확인된 원인
- 캡처의 오류는 Google Drive VOD가 아니라 실시간 HLS 방송입니다.
- 현재 master manifest, 영상 목록, 오디오 목록, 실제 영상 조각은 모두 Google 저장소에서 HTTP 200으로 정상 생성되고 있습니다.
- 하지만 응답에 브라우저 교차 출처 허용 헤더가 없습니다. 사이트의 플레이어가 응답 내용을 읽지 못하면서 실제 200 응답을 `networkError / http: 0`으로 처리하고 있습니다.
- DB 상태도 `STREAMING`이고 현재 방송 주소도 올바르므로 OBS, GCP 채널 생성, mux 분리, 파일 생성 문제가 아닙니다.

## 변경 내용
1. 기존 출력 버킷 준비/복구 로직에 HLS용 CORS 설정을 추가합니다.
   - 허용 출처: 게시 사이트, 미리보기 사이트, 로컬 미리보기
   - 허용 방식: `GET`, `HEAD`
   - 영상 Range 요청에 필요한 응답 헤더 노출
2. 방송 프로비저닝 때 공개 읽기 권한뿐 아니라 CORS 설정도 확인합니다.
3. 관리자 `출력 버킷 복구` 기능이 현재 버킷의 CORS도 즉시 교정하도록 합니다.
4. 관리자 진단 결과에 공개 권한과 CORS 상태를 각각 표시해 같은 문제가 재발하면 바로 구분합니다.
5. 수정된 방송 함수를 배포한 뒤 기존 버킷 복구를 실행하고, manifest·하위 목록·영상 조각 응답 헤더와 실제 플레이어를 다시 확인합니다.

## 영향과 안전장치
- 방송 시작·종료, OBS 주소, GCP 채널/Input 생성 방식, 저장 경로는 변경하지 않습니다.
- 영상은 계속 Google 저장소에서 시청자에게 직접 전달되므로 Lovable Cloud 영상 전송 비용은 늘지 않습니다.
- 기존 진행 중인 방송 파일을 삭제하거나 방송을 재시작하지 않습니다.
